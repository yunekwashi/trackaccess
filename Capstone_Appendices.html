Appendix B: API Documentation

This section outlines the RESTful API endpoints utilized by the TrackAccess backend services to facilitate communication between the hardware scanner, the database, and the frontend interfaces.

1. Register Student (/backend/register_student.php)

  • Description: Registers a new student into the system and binds an RFID UID to their profile.
  • Method: POST
  • Content-Type: application/json
  • Request Format: 
    {
  "student_id": "2023-0001",
  "name": "Juan Dela Cruz",
  "rfid_uid": "A1 B2 C3 D4",
  "course": "BSIT",
  "year_level": "3"
}
  • Response (Success): 
    {
  "success": true,
  "message": "Student registered successfully."
}

2. Update Student Data (/backend/update_student.php)

  • Description: Updates an existing student's data, including manual point adjustments or status changes.
  • Method: POST
  • Request Format: 
    {
  "student_id": "2023-0001",
  "name": "Juan Dela Cruz",
  "course": "BSIT",
  "points": 10,
  "isActive": true
}
  • Response (Success): 
    {
  "success": true,
  "message": "Student updated successfully"
}

3. Hardware RFID Scan (/backend/scan_rfid.php)

  • Description: Native endpoint called by the Arduino/ESP32 scanner when an RFID card is physical tapped.
  • Method: POST
  • Request Format: 
    {
  "uid": "A1 B2 C3 D4"
}
  • Response (Success): 
    {
  "success": true,
  "message": "Scan recorded successfully"
}

4. Fetch Leaderboards & Students (/backend/get_students.php)

  • Description: Retrieves all registered students. The application uses this to generate the Leaderboards based on accumulated points.
  • Method: GET
  • Response Format: 
    [
  {
    "id": 1,
    "student_id": "2023-0001",
    "name": "Juan Dela Cruz",
    "course": "BSIT",
    "yearLevel": "3",
    "uid": "A1 B2 C3 D4",
    "points": 50,
    "visits": 12,
    "isActive": true
  }
]

5. Admin Reporting / Activity Logs (/backend/get_all_scans.php)

  • Description: Returns the chronological audit trail of all actions and scans for the Admin Report Dashboard.
  • Method: GET
  • Response Format: 
    {
  "success": true,
  "count": 1,
  "logs": [
    {
      "id": "1",
      "student_id": "2023-0001",
      "student_name": "Juan Dela Cruz",
      "action": "registered",
      "details": "Registered new RFID.",
      "timestamp": "2024-05-01 10:00:00"
    }
  ]
}

Appendix E: User Manual and Deployment Guide

1. System Installation & Requirements

  • Operating System: Windows 10 or Windows 11
  • Dependencies: PHP 8.0+, MySQL Database (e.g., via XAMPP)
  • Hardware: Minimum 4GB RAM, Arduino Uno/Nano with RC522 RFID Module

2. Administrator: Launching the System

  1. Start the Backend Server:
    • Locate the trackaccess master folder on the computer.
    • Navigate to the backend/ folder.
    • Right-click the run_standalone.ps1 file and select "Run with PowerShell".
    • This will automatically start the database connections and API framework. Do not close this terminal window while the system is in use.
  2. Start the Frontend Dashboard:
    • Navigate to the frontend application executable (usually located in build/windows/runner/Release/trackaccess.exe).
    • Double click to open the visual TrackAccess Dashboard interface.

3. Hardware Operation (RFID Scanning)

  1. Ensure the Arduino RFID scanner is securely attached via USB to the host computer.
  2. Wait for the device to briefly flash, indicating it is powered and ready to accept input.
  3. To scan, a user must hover their ID card within 2 inches of the RFID plate until a beep is heard.
  4. The system will automatically record the scan in real-time.

4. Registering a New Student

  1. Login to the frontend dashboard using Administrator credentials.
  2. Navigate to the Add Member/Registration menu.
  3. Type the user's Student ID, Name, Course, and Year Level into the text boxes.
  4. Tap an unassigned RFID card on the scanner to link the physical UID code.
  5. Click Register to save the profile to the database.

5. Viewing Leaderboards and Reports

  1. On the main dashboard window, click Leaderboard to view the real-time ranking of students based on library visits and points.
  2. Click Admin Reports to view a chronological audit trail showing exactly who logged into the library, when they logged in, and any point modifications made by admins.
